# Codex Cove 0.6.1
<!-- release-tag: v0.6.1 -->

Codex Cove 0.6.1 adds independent appearance controls for the full Workspace
window and makes privacy redaction explain its active cause. These notes
describe the source candidate bound to `v0.6.1`; signing, notarization,
publication, and Homebrew availability remain prospective until the protected
release workflow finishes.

Source tag: `v0.6.1`

## Highlights

- Workspace can follow the current macOS appearance or remain Light or Dark.
  The choice is available in the Workspace toolbar and Settings, persists
  locally, and does not change the island theme.
- A content-free Workspace banner distinguishes explicit Privacy On,
  automatic capture-app protection, and the temporary macOS lock safeguard.
- Bringing Workspace forward explicitly now refreshes capture privacy so a
  stale locked state cannot keep details hidden after the Mac is interactive.
- Workspace, Settings, and User Guide documentation explains the appearance
  choice, redaction reasons, and recovery path. Native hover help and
  accessibility identifiers cover the new controls.
- Native regression coverage verifies actual Light and Dark rendering,
  settings persistence, Privacy On redaction, and Privacy Off lock recovery.

## Installation and compatibility

Codex Cove 0.6.1 is intended for Apple Silicon Macs running macOS 14 or newer.
Remote helpers support Apple Silicon and Intel macOS plus arm64 and x86_64
Linux-musl hosts. Codex CLI 0.147.0 or newer remains required for Workspace
thread discovery and control.

The release retains the `local.chris.codexcove` bundle identity and upgrades an
existing Homebrew installation in place while preserving settings, custom
themes, content-free session metadata, and explicitly saved Workspace content.
After the immutable release and generated Cask handoff are published and
merged, update with:

```sh
brew update
brew upgrade --cask cdimartino/codex-cove/codex-cove
```

The native `codex` command remains untouched. `codex-cove launch` remains the
explicit path for a broker-routed CLI session.

## Security and privacy

The new appearance setting is content-free and uses Cove's existing private
settings file. This patch does not add credentials, connectors, telemetry, or
new persisted task content.

Unsaved composer text, submitted prompts, upstream titles, assistant output,
approvals, questions, commands, diffs, and transcripts remain memory-only.
Privacy redaction still removes protected Workspace fields from rendering,
Accessibility, and search matching. Refreshing a stale lock state occurs only
when the user explicitly brings the Workspace window forward; explicit Privacy
On and automatic capture-app protection remain authoritative.

The protected distribution workflow will fail closed unless the reviewed tag
matches protected `main`, candidate evidence and tests pass, Developer ID
signing succeeds, Apple notarization and Gatekeeper checks succeed, and every
downloadable asset is covered by `SHA256SUMS`.

## Known boundaries

- The graphical app remains Apple Silicon only; Intel macOS support applies to
  the optional remote helper, not the app bundle.
- The appearance choice applies only to the full Workspace window. Island
  palette, material, opacity, and custom-theme controls remain independent.
- Explicit Privacy On and active automatic capture-app privacy still hide
  sensitive Workspace fields and disable prompt interaction in Cove.
- Homebrew availability follows the separate generated-Cask pull request; an
  immutable GitHub release alone does not update the tap's default branch.
