# Codex Cove 0.5.1
<!-- release-tag: v0.5.1 -->

Codex Cove 0.5.1 fixes the collapsed island's native macOS backdrop rendering.
The release keeps the panel and its controls fully legible while allowing the
desktop behind the island to remain visibly transmitted through the configured
blur strength. These notes describe the source candidate bound to `v0.5.1`;
signing, notarization, publication, and Homebrew availability remain
prospective until the protected release workflow finishes.

Source tag: `v0.5.1`

## Highlights

- The collapsed island uses AppKit's through-window backdrop material for all
  enabled blur presets instead of dense HUD or popover fills that could make
  the surface appear opaque.
- Thin, Regular, and Thick blur settings now vary the native effect's strength
  independently from the configured theme tint opacity. Text, controls, and
  status residents are not dimmed as a side effect.
- Privacy mode and macOS Reduce Transparency behavior remain intentionally
  opaque, preserving the existing accessibility and privacy guarantees.
- A compositor regression test compares the same rendered island pixels over
  light and dark controlled backdrops, preventing theme gradients from masking
  a future transparency regression.

## Installation and compatibility

Codex Cove 0.5.1 is intended for Apple Silicon Macs running macOS 14 or newer.
It retains the `local.chris.codexcove` bundle identity and upgrades an existing
Homebrew installation in place while preserving settings and custom themes.
Codex CLI 0.145.0 or newer remains required.

After the immutable release and generated Cask handoff are published and
merged, update with:

```sh
brew update
brew upgrade --cask cdimartino/codex-cove/codex-cove
```

The native `codex` command remains untouched. `codex-cove launch` remains the
explicit path for a broker-routed CLI session.

## Security and privacy

The transparency change does not expand persistence, networking, or account
access. Theme tint settings remain local, privacy mode still redacts sensitive
fields, and Reduce Transparency still selects an opaque fallback surface.

The protected distribution workflow will fail closed unless the reviewed tag
matches protected `main`, candidate evidence and tests pass, Developer ID
signing succeeds, Apple notarization and Gatekeeper checks succeed, and every
downloadable asset is covered by `SHA256SUMS`.

## Known boundaries

- The graphical app remains Apple Silicon only; Intel macOS support applies to
  the optional remote helper, not the app bundle.
- Reduce Transparency intentionally trades the native transmitted backdrop for
  an opaque surface, as required by the accessibility setting.
- Homebrew availability follows the separate generated-Cask pull request; an
  immutable GitHub release alone does not update the tap's default branch.
