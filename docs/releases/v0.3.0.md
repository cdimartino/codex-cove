# Codex Cove 0.3.0
<!-- release-tag: v0.3.0 -->

Codex Cove 0.3.0 makes the task queue faster to operate, fixes theme color and
opacity rendering in installed builds, and hardens the Codex CLI shim against
large app-server responses and disconnected sessions. These notes describe the source candidate
bound to `v0.3.0`; signing, notarization, publication, and Homebrew availability
remain prospective until the protected release workflow finishes.

Source tag: `v0.3.0`

## Highlights

- Every queue section can be collapsed or expanded and moved up or down. Cove
  persists the chosen section order and collapsed state between launches.
- Recently Finished includes an **Archive Completed** action. Bulk archive is
  fail-safe: it excludes sessions with pending direct requests, mixed states,
  failures, interruptions, or any snapshot that is not completed.
- Task rows expose Pin, Remind Me, Mark Read, and Archive from the native
  right-click menu as well as the visible actions menu.
- Clicking a task row now opens its exact Codex origin directly. The separate
  Details or Review control remains available for Cove's focused surface.
- Installed collapsed and expanded surfaces now use the selected theme color
  and configured opacity. Hard-coded and opaque child backgrounds no longer
  mask those appearance settings.
- The broker now accepts the approximately 3.5 MiB `app/list` response emitted
  by Codex 0.146 after MCP startup. Reinstalling migrates the legacy 1 MiB frame
  limit to 8 MiB, and the app-server smoke test exercises that response.
- Broker input disconnects, output-worker failures, and WebSocket closure now
  terminate the app-server and its MCP descendants as one process group and
  reap the child instead of leaving a permanently spinning TUI or orphaned MCP
  bridges.
- Cove now prefers the current non-Cove `codex` binary found on `PATH` over an
  older still-valid versioned path in `helper-config.json`. Reinstall and
  upgrade flows persist the refreshed path while preserving other settings.
- UI coverage verifies persisted collapse and reorder behavior, safe bulk
  archive, right-click actions, direct origin opening, and rendered pixel
  changes for both collapsed and expanded opacity.
- CI can re-render a previously published Homebrew Cask from its verified
  immutable release assets after the source version advances. Rendering a new
  release remains bound to the current synchronized source version.

## Installation and compatibility

Codex Cove 0.3.0 is intended for Apple Silicon Macs running macOS 14 or newer.
It retains the `local.chris.codexcove` bundle identity and upgrades the
existing Homebrew installation in place while preserving settings.

After the immutable release and generated Cask handoff are published and
merged, update with:

```sh
brew update
brew upgrade --cask cdimartino/codex-cove/codex-cove
```

The release continues to support Terminal.app, iTerm2, tmux, WezTerm, VS Code,
Cursor, selected SSH hosts, and Codex Desktop exact-origin navigation. macOS
Accessibility or Automation permissions may still be required for native
window focus.

## Security and privacy

Bulk archive writes only opaque session identifiers already used by Cove's
local archive store. Section preferences contain enum values only. Neither
feature adds network access or persists prompts, responses, commands, diffs,
approval contents, or question contents.

The protected distribution workflow will fail closed unless the reviewed tag
matches protected `main`, all candidate evidence and tests pass, Developer ID
signing succeeds, Apple notarization and Gatekeeper checks succeed, and every
downloadable asset is covered by `SHA256SUMS`.

The app archive is expected to be Developer ID signed, notarized, stapled, and
accepted by Gatekeeper before publication. The Homebrew Cask is staged only
after the workflow re-downloads and verifies the immutable release bytes.

## Known boundaries

- The graphical app remains Apple Silicon only; Intel macOS support applies to
  the optional remote helper, not the app bundle.
- Section reordering uses accessible Move Up and Move Down menu actions rather
  than drag-and-drop.
- Archive Completed intentionally leaves failed, interrupted, active,
  attention-needed, and mixed-status sessions visible for individual review.
- Custom themes remain local files and must be exported and imported manually
  when moving them between Macs.
- Homebrew availability follows the separate generated-Cask pull request; an
  immutable GitHub release alone does not update the tap's default branch.
