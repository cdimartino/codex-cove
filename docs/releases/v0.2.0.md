# Codex Cove 0.2.0
<!-- release-tag: v0.2.0 -->

Codex Cove 0.2.0 introduces the first planned binary distribution of the
local-only macOS companion for Codex CLI and Codex Desktop. It brings task
activity, approvals, questions, and exact-origin navigation into a compact
notch-aligned island while keeping task content out of Cove's durable storage.

These notes describe the contents bound to `v0.2.0`; they are not a mutable
status page for signing, notarization, publication, or Homebrew availability.
The GitHub release page and the Cask on the repository's default branch are the
authoritative availability records.

Source tag: `v0.2.0`

## Highlights

- A three-state interface moves between the collapsed island, an
  attention-first task queue, and focused approval or question controls.
- Task residents and queue rows distinguish active, waiting, completed,
  failed, blocked, and interrupted work. Search, pinning, unread state,
  reminders, plans, recoverable local archives, and configurable sounds and
  notifications are included.
- Exact-origin navigation can return to the initiating Terminal.app or iTerm2
  session, tmux or WezTerm pane, VS Code or Cursor terminal and window, selected
  SSH host, or Codex Desktop task. Missing or ambiguous origins fail closed.
- Approval scopes use select-then-confirm interaction, single-flight delivery,
  retryable failures, and authoritative request checks. Unsupported requests
  remain in the native Codex client.
- The bundled VS Code and Cursor extension creates routed terminals, registers
  existing terminals, and verifies both terminal selection and native editor
  window focus without persisting working directories, shell commands, or task
  content.
- The candidate includes fixes for two pre-release P1 exact-window defects:
  VS Code and Cursor could previously select the correct routed terminal
  without activating the uniquely bound native editor window. The focus
  transaction now requires a single content-free window anchor, raises that
  exact window, and reconfirms terminal and window focus before reporting
  success.
- Native Glass, Retro Terminal, and Minimal OLED styles include five palettes,
  custom themes, scalable text, configurable geometry, semantic contrast, and
  Reduce Motion support.
- A current-user installer manages the app, helper, Codex shim and hooks,
  editor extension, schemas, and optional remote helpers with checksum-gated
  repair, rollback, and ownership checks.
- Doctor verifies the installed bundle identity and tree, signatures, managed
  helper and links, exact hook ownership, editor targets, schemas, private
  event socket, and optional remote helper checksums.

## Installation and compatibility

The release app is intended for Apple Silicon Macs running macOS 14 or newer
and requires Codex CLI 0.145.0 or newer. VS Code 1.92 or newer and compatible
Cursor builds are optional. Terminal and editor exact-focus features require
the corresponding macOS Automation or Accessibility permission; installation
does not approve those permissions or Codex hook trust on the user's behalf.

The canonical installed location is `~/Applications/Codex Cove.app`. After an
immutable GitHub release is published and its generated Cask passes the staged
Homebrew lifecycle review and lands on the default branch, the intended Cask
commands are:

```sh
brew tap cdimartino/codex-cove https://github.com/cdimartino/codex-cove.git
brew install --cask cdimartino/codex-cove/codex-cove
```

Until that release-to-tap handoff lands, use the source installation workflow
or a manually downloaded release only after verifying its aggregate
`SHA256SUMS`, Developer ID signature, notarization ticket, and Gatekeeper
assessment.

The optional remote helper bundle covers Apple Silicon and Intel macOS plus
statically linked arm64 and x86_64 Linux-musl targets. Remote routing is opt-in
for explicitly selected, preconfigured SSH aliases.

An existing local or ad-hoc build at the same bundle identifier may be treated
by macOS as a different trusted client from the Developer ID distribution.
Users may need to remove the older Codex Cove entries from Accessibility or
Automation, enable the installed release again, and relaunch it.

For a later Cask-backed upgrade, refresh Homebrew metadata and upgrade the
installed Cask:

```sh
brew update
brew upgrade --cask cdimartino/codex-cove/codex-cove
```

Version `0.2.0` is the planned first public Cask, so its release handoff uses a
same-version reinstall rather than a prior-Cask upgrade. If a Cask install or
replacement must be rolled back, first remove the managed integration and app
while retaining Cove settings:

```sh
brew uninstall --cask cdimartino/codex-cove/codex-cove
```

Then reinstall a separately verified immutable release or return to the source
workflow with `make install`. Do not move the `v0.2.0` tag or substitute assets
under it. Avoid `brew zap` when settings must survive; zap is the explicit
full-data removal path.

## Security and privacy

Codex Cove has no account system, telemetry, advertising, cloud backend,
licensing service, online updater, or private Codex storage access. Prompts,
responses, commands, diffs, token values, and approval or question details are
not written to Cove's durable task store. It persists settings and bounded,
content-free metadata such as opaque identifiers, source, state, timestamps,
unread/reminder state, and opaque terminal-location metadata.

Runtime files, local sockets, settings, and install metadata are restricted to
the current user. The app validates socket type, ownership, mode, size, and
identity before use. Local and remote decision success means that a complete
validated private-socket frame was written; it does not claim that downstream
Codex processing accepted or completed the action.

The distribution workflow is designed to fail closed unless the candidate
receipt is complete, the tag names the exact protected-default-branch commit,
dependencies and tests pass, the app and macOS helpers use the configured
Developer ID Application identity, notarization and Gatekeeper assessment
succeed, and every other downloadable asset is covered by the published
checksum manifest. No certificate archive, private key, notarization
credential, or raw test log belongs in the release assets.

## Release assets

The protected workflow's immutable release-asset contract for `v0.2.0` is:

- `Codex-Cove-0.2.0-macos-arm64.zip`, containing the signed, notarized, and
  stapled app with its embedded helper, extension, schemas, and remote helpers;
- `Codex-Cove-0.2.0.vsix`, the bundled VS Code and Cursor extension;
- `Codex-Cove-0.2.0-remote-helpers.tar.gz`, with four checksummed target
  helpers;
- the deterministic source-candidate manifest and its SHA-256 digest;
- the privacy-safe completed release receipt;
- `codex-cove.rb`, rendered from the final app archive version and checksum;
  and
- `SHA256SUMS`, covering every other published asset.

Public-repository builds are also intended to receive GitHub artifact
attestations. The generated Cask is staged only after the workflow re-downloads
the immutable public release and verifies the exact released bytes.

## Known boundaries

- The application bundle is Apple Silicon only. The Intel macOS executable is
  a remote helper, not an Intel build of the graphical app.
- Exact editor focus supports the documented VS Code and Cursor API-compatible
  versions. Other editors are not part of the primary compatibility matrix.
- iTerm2 exact-origin support remains in the product, but the `0.2.0` owner
  placement batch intentionally requires one Terminal.app task, three VS Code
  tasks, three Cursor tasks, and zero iTerm2 tasks. Its iTerm2 appearance and
  exact-origin rows are therefore `not-required` for that batch, not claimed as
  completed and not removed from the supported-environment documentation.
- Cross-origin upstream identifier collisions are rejected from simultaneous
  presentation rather than merged or misrouted; displaying both would require
  a later schema and presentation-identity change.
- Remote hosts require explicit setup and non-interactive SSH authentication.
  Cove does not create or manage SSH credentials.
- Homebrew availability is separate from immutable binary publication and
  begins only after the generated first-release Cask passes a clean install,
  Doctor, reinstall/uninstall, and protected pull-request merge. Check the
  default branch for `Casks/codex-cove.rb` rather than inferring availability
  from these immutable notes.
