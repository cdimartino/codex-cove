# Codex Cove 0.8.1
<!-- release-tag: v0.8.1 -->

Codex Cove 0.8.1 makes management-command help and uninstall argument handling
fail closed. It retains all Workspace artifact, favicon, and exact-agent
control improvements from 0.8.0 while correcting a longstanding command-line
safety defect found during post-publication validation. These notes describe
the source candidate bound to `v0.8.1`; signing, notarization, publication, and
Homebrew availability remain prospective until the protected release workflow
finishes.

Source tag: `v0.8.1`

## Highlights

- `codex-cove uninstall --help` and `codex-cove uninstall -h` now print usage
  and exit successfully before reading or changing installation state.
- Unknown or misspelled uninstall arguments are rejected before Cove resolves
  the user layout, acquires a mutation lock, cleans editor extensions, or
  removes any file.
- The same early help handling protects the `install` and `repair` management
  routes without adding a parser dependency or changing their valid options.
- Binary-level regression coverage runs the real helper against an isolated
  home and proves both help and a misspelled flag preserve a Workspace
  sentinel byte-for-byte.

## Installation and compatibility

Codex Cove 0.8.1 is intended for Apple Silicon Macs running macOS 14 or newer.
Remote helpers support Apple Silicon and Intel macOS plus arm64 and x86_64
Linux-musl hosts. Codex CLI 0.147.0 or newer remains required for Workspace
thread discovery and control.

This patch keeps Workspace schema version 3, the `local.chris.codexcove`
bundle identity, and all existing settings and session formats. It upgrades
0.8.0 in place. Homebrew did not promote the generated 0.8.0 Cask after the
uninstall-argument defect was discovered; the corrected 0.8.1 Cask supersedes
that staging branch.

After the immutable release and generated Cask handoff are published and
merged, update with:

```sh
brew update
brew upgrade --cask cdimartino/codex-cove/codex-cove
```

The native `codex` command remains untouched. `codex-cove launch` remains the
preferred path for a continuously broker-routed CLI session.

## Security and privacy

Before this fix, any unrecognized token after `uninstall` could fall through
to a default full uninstall. That path could remove the verified app,
integration, and support directory, including user-authored Workspace state,
settings, and content-free session metadata. Version 0.8.1 rejects those
tokens before any filesystem or editor operation.

Valid uninstall operations retain their existing ownership, permission,
rollback, and package-manager boundaries. `--plan`, `--keep-settings`, and
`--keep-app` remain the only accepted uninstall options. No telemetry,
connector, credential, favicon-network, or prompt-persistence behavior changes
in this patch.

The protected distribution workflow will fail closed unless the reviewed tag
matches protected `main`, candidate evidence and tests pass, Developer ID
signing succeeds, Apple notarization and Gatekeeper checks succeed, and every
downloadable asset is covered by `SHA256SUMS`.

## Known boundaries

- `uninstall --plan`, `--keep-settings`, and `--keep-app` remain real
  management options. Help and invalid arguments are non-mutating, but a valid
  uninstall still requires the same deliberate operator care as before.
- Workspace files already migrated to schema version 3 remain intentionally
  unreadable by Cove versions older than 0.8.0; those older versions fail
  closed instead of rewriting newer ordering data.
- Homebrew availability follows a separate generated-Cask pull request; an
  immutable GitHub release alone does not update the tap's default branch.
