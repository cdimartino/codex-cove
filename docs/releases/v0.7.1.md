# Codex Cove 0.7.1
<!-- release-tag: v0.7.1 -->

Codex Cove 0.7.1 restores Workspace prompting for completed and idle local CLI
tasks that Cove discovered through hooks rather than its routed launcher. These
notes describe the source candidate bound to `v0.7.1`; signing, notarization,
publication, and Homebrew availability remain prospective until the protected
release workflow finishes.

Source tag: `v0.7.1`

## Highlights

- Completed and idle hook-observed Local CLI tasks now offer **Start Turn** in
  the Workspace inspector instead of requiring an exact jump back to Codex.
- Before sending, Cove asks the public local Codex app-server to verify the
  exact CLI thread and safe idle state, then resumes it without returning turn
  history.
- Approvals and questions from Cove-started turns continue through the existing
  decision UI. Later steering requires the exact turn that Cove owns.
- Pending requests, wrong origins, missing threads, ambiguous identifiers, and
  active hook-only tasks without an exact turn identifier still fail closed.
- Native regression coverage exercises exact source validation, unloaded-thread
  resume, start and steer delivery, pending-request rejection, and the enabled
  completed-task composer.

## Installation and compatibility

Codex Cove 0.7.1 is intended for Apple Silicon Macs running macOS 14 or newer.
Remote helpers support Apple Silicon and Intel macOS plus arm64 and x86_64
Linux-musl hosts. Codex CLI 0.147.0 or newer remains required for Workspace
thread discovery and control.

The release retains the `local.chris.codexcove` bundle identity and upgrades an
existing Homebrew installation in place while preserving settings, custom
themes, content-free session metadata, and explicitly saved Workspace content.
After the immutable release and generated Cask handoff are published and
merged, update with:

```sh
brew update
brew upgrade --cask cdimartino/codex-cove/codex-cove
```

The native `codex` command remains untouched. `codex-cove launch` remains the
preferred path for a continuously broker-routed CLI session.

## Security and privacy

The hook-only fallback reads only the selected thread's public metadata without
turns, requires an exact CLI source and safe state, and resumes with turns
excluded from the response. It does not ingest a transcript into Cove.

Composer text and submitted prompts remain memory-only. Cove rechecks the
selected composite identity, route, operation, active turn, pending requests,
and unchanged composer text before delivery. It never retries an uncertain
prompt automatically.

The protected distribution workflow will fail closed unless the reviewed tag
matches protected `main`, candidate evidence and tests pass, Developer ID
signing succeeds, Apple notarization and Gatekeeper checks succeed, and every
downloadable asset is covered by `SHA256SUMS`.

## Known boundaries

- Active hook-only tasks remain unavailable until Cove owns their exact active
  turn identifier; open those tasks in Codex or use `codex-cove launch` for
  future routed sessions.
- The public Codex `turn/start` operation has no atomic idle precondition. A
  different client starting the same thread in the final delivery race can
  cause Codex itself to treat the submitted input as a steer.
- A durable app-server daemon is optional when the supported direct stdio
  fallback passes Doctor and the non-prompting smoke checks.
- Homebrew availability follows the separate generated-Cask pull request; an
  immutable GitHub release alone does not update the tap's default branch.
